# 单文档事实问答诊断与修复设计

## 背景

平衡型 Auto 路由评测中，多文档答案正确性达到 0.900，但八道单文档
事实题的答案正确性只有 0.738。两个 Cookie 问题表现最差：

- `cookie-02` 没有命中标注的 Cookie 文档，文档召回率和答案正确性均为 0。
- `cookie-01` 命中了正确文档，但必要事实覆盖率只有 0.4，答案正确性为 0。

这两种失败不能统一归因于检索。前者是明确的文档级漏召回，后者可能发生
在片段召回、融合、重排、上下文组织或答案生成任一阶段。本阶段先建立可审查
的分阶段证据，再只修复真正的根因。

## 目标

- 复现并定位 `cookie-01`、`cookie-02` 的失败阶段。
- 为检索流水线建立不调用真实 LLM 的固定回归测试。
- 以通用规则修复确认的根因，不针对具体评测词或文档名硬编码。
- 将单文档事实题文档召回率提升到至少 0.90。
- 将单文档事实题答案正确性提升到至少 0.85。
- 保持多文档答案正确性不低于 0.80。

## 非目标

- 不新增前端评测或诊断界面。
- 不更换 Embedding、重排或 LLM 供应商。
- 不扩充整体评测集。
- 不重构与失败根因无关的检索代码。
- 不通过回答提示词掩盖尚未定位的检索问题。
- 不为 Cookie、Max-Age、Expires 或具体文件名添加特例。

## 分阶段诊断

诊断脚本对每个失败问题采集以下数据：

1. BM25 候选、分数和排名。
2. 向量候选、距离或分数和排名。
3. RRF 融合后的候选、组成来源和排名。
4. Cross-encoder 重排前后的顺序与分数。
5. 最终交给回答模块的上下文和文档元数据。
6. 答案实际使用的引用片段。

诊断必须保留每个阶段的稳定 chunk/document 标识，使同一片段可以跨阶段追踪。
报告同时记录当前检索配置、`top_k`、候选扩召回倍数、重排开关和模型名称。

诊断报告存放在 `docs/diagnostics/`，只记录问题、证据、根因和结论，不包含
API Key、完整环境变量或无关知识库数据。

## 根因决策

### BM25 漏召回

检查查询与文档的：

- 大小写归一化；
- 连字符和标点；
- 英文属性名分词；
- 中英文混合 token；
- 精确术语是否被拆散。

只修改通用 token 规范化和索引/query 对称性。

### 向量检索漏召回

检查：

- query embedding 是否使用正确模型和配置；
- 目标片段是否已进入向量库；
- chunk 边界是否把关键事实拆开；
- 候选扩召回数量是否足够。

只有证据表明问题普遍存在时才调整 chunk 或候选参数。

### RRF 融合压低正确片段

记录正确片段在 BM25、向量和融合结果中的排名。如果单路排名合理但融合后
跌出候选，调整通用融合参数或候选池；不为单一问题增加权重特例。

### Cross-encoder 误杀

对比重排前后目标片段排名。若目标片段稳定被错误降权，检查重排输入、截断、
异常降级和分数方向。只有重复结果确认后才调整阈值或候选数量。

### 上下文正确但答案错误

如果必要事实片段已经进入最终上下文，检索视为通过。此时检查：

- 上下文排序是否让相关片段被长内容淹没；
- 相邻引用编号是否正确；
- 回答提示是否要求覆盖问题中的每个属性；
- 模型是否存在随机波动。

只有上下文组织或回答约束存在通用缺陷时才修改回答层。

### 模型波动

对上下文相同但答案不稳定的样本重复生成三次。若失败没有稳定模式，不硬编码
修复；报告成功率和方差，并把问题归入后续模型可靠性工作。

## 修复原则

- 每个代码改动必须对应诊断报告中的一条证据。
- 优先修复 query/index 对称性、分数方向、截断等确定性缺陷。
- 参数调整必须同时检查其他题目的排名变化。
- 不增加新的 LLM 调用。
- 不显著增加检索延迟。
- 如果没有发现通用实现缺陷，允许以“无需代码修复”结束本阶段。

## 测试

### 检索回归测试

固定测试数据中包含：

- 连字符英文属性名；
- 大小写变体；
- 中英文混合查询；
- 含相似干扰术语的无关片段；
- 目标事实位于段落中部的片段。

测试分别断言：

- BM25 top-k 包含目标片段；
- 向量候选池包含目标片段；
- RRF 后目标片段未被错误淘汰；
- 启用重排后目标片段仍位于最终 top-k。

测试使用 fake embedding、固定候选和 fake reranker，不访问外部服务。

### 真实回归

修复完成后只运行一次 Auto 18 题评测，并与已记录的 Auto v2 比较。保持：

- 相同知识库和固定语料；
- `top_k=5`；
- Auto 2/6 预算；
- Web 搜索关闭；
- 相同确定性指标与 LLM Judge。

## 错误处理

- 任一外部诊断调用失败时保存已完成阶段，不覆盖已有结果。
- Embedding、reranker 或 LLM 超时分别记录，不归类为算法失败。
- 402、认证和配置错误立即停止真实回归，不反复重试。
- 重复实验使用同一检索上下文，避免把检索波动与生成波动混为一谈。

## 产物

- `docs/diagnostics/` 下的分阶段诊断报告。
- 新增或更新的检索回归测试。
- 与根因直接对应的最小实现改动。
- Auto 修复前后对比汇总。
- README 和 DEVELOPMENT 中更新后的最终可信结果。

## 验收标准

- 两个 Cookie 失败样本都有可追踪的分阶段证据和明确归因。
- 单文档事实题文档召回率至少 0.90。
- 单文档事实题答案正确性至少 0.85。
- 多文档答案正确性不低于 0.80。
- 无答案正确率保持 1.00。
- 不增加 LLM 调用次数。
- 检索延迟无明显上升。
- 现有测试和新增测试全部通过。
