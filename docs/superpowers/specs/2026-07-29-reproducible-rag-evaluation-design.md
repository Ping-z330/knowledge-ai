# 可复现 RAG 评测设计

## 背景

当前 `backend/eval_dataset.jsonl` 从历史问答记录生成，包含重复问题，并将模型旧答案作为参考答案。它还指向另一套混合知识库，无法稳定复现，也不足以支撑 Traditional RAG 与 Agentic RAG 的质量对比。

项目已经准备好独立的 `RAG Evaluation` 知识库，其中包含四份 MDN 文档和 RFC 9111 PDF，五份文档均已解析和索引。本设计以这套固定语料建立小型、可审查、可重复运行的基准。

## 目标

- 建立 18 道人工标注、版本化的固定评测题。
- 公平比较 `standard`、`agentic` 和 `auto` 三种运行模式。
- 同时度量检索、回答质量、引用、拒答能力、延迟和 Agentic 成本。
- 保存逐题原始数据与汇总报告，允许复查和复现实验。
- 用真实实验结果替换 README 和 DEVELOPMENT 中缺乏可复现依据的旧结论。

## 非目标

- 不建设通用评测平台或 Web 管理界面。
- 不使用生产历史问答作为 ground truth。
- 不在主实验中启用 Web 搜索；Web 回退只作为显式开启的独立实验。
- 不追求大型统计基准；本轮重点是建立可信、可维护的最小闭环。

## 评测集

评测集存放在 `backend/eval/benchmark.jsonl`。每行是一道独立题目，包含：

- `id`：稳定且唯一的题目 ID。
- `category`：题型。
- `question`：用户问题。
- `reference_answer`：人工编写的参考答案。
- `relevant_documents`：应提供证据的文档文件名列表。
- `answerable`：固定语料是否足以回答。
- `required_facts`：正确答案必须覆盖的原子事实。
- `notes`：可选的标注说明。

题型包括：

1. 单文档事实题：验证基础检索和事实准确性。
2. 多文档综合题：验证查询拆解、跨文档检索和综合能力。
3. MDN 与 RFC 对照题：验证解释性资料与规范性资料的来源选择。
4. 无答案题：验证资料不足时的拒答能力。

题目只依赖 `evaluation_corpus/README.md` 列出的五份内容文档，不依赖该目录的 README 或许可证文件。

## 运行架构

### `benchmark_runner.py`

运行器读取固定数据集，对每道题分别执行指定模式，并采集：

- 最终答案；
- 检索来源及文档元数据；
- trace；
- 总耗时；
- 检索次数、重试次数和 Web 回退次数；
- 异常信息。

命令行参数至少包括：

- `--kb-id`：目标知识库 ID，禁止将本机 UUID 写死在代码中。
- `--modes`：运行模式，默认包含 `standard agentic auto`。
- `--dataset`：评测集路径。
- `--limit`：用于快速冒烟验证。
- `--output-dir`：结果目录。
- `--resume`：从已有逐题结果继续，已成功完成的 `(question_id, mode)` 不重复执行。
- `--allow-web-search`：显式启用 Web 回退；默认关闭。

三种模式必须调用产品实际使用的统一问答执行路径，不能为评测复制一套实现。所有模式使用相同问题、`top_k` 和知识库。主实验关闭 Web 搜索，确保答案只基于固定语料。

### `benchmark_metrics.py`

指标模块只读取运行产物并评分，不负责执行问答。这样可在不重复调用回答模型的情况下修正或新增评分逻辑。

确定性指标包括：

- 文档命中率：来源是否覆盖 `relevant_documents`。
- 必要事实覆盖率：答案是否覆盖 `required_facts`。
- 引用有效率：引用编号是否能映射到实际返回来源。
- 无答案正确率：不可回答题是否明确说明资料不足，且未编造具体答案。
- 成功率和失败数。
- 延迟分布。
- 检索、重试与 Web 回退次数。

必要事实匹配采用标注中定义的规范化关键词或等价短语，不依赖 LLM。每道题保留单项判断细节，避免只有一个不可解释的总分。

LLM Judge 指标包括：

- Faithfulness：回答是否有上下文支持。
- Answer correctness：回答是否与参考答案一致。
- Answer relevancy：回答是否直接回应问题。

Judge 使用项目配置的 OpenAI 兼容 LLM。Judge 调用失败时保留确定性指标，将对应 Judge 项标记为未评分，不把失败样本静默排除或计为零分。

## 产物

每次实验在 `backend/eval/results/` 下生成：

- 带时间戳的逐题 JSONL，保存输入、运行模式、答案、来源、trace、耗时和错误。
- 汇总 JSON，便于程序化比较。
- 汇总 Markdown，按模式和题型展示指标、成功题数及失败原因。

报告必须同时给出分数的分母。例如 Judge 只完成 16/18 题时，报告显示 `n=16`，不得表现为完整样本结果。

`backend/eval/README.md` 记录：

- 如何创建或确认独立评测知识库；
- 应上传哪些文档；
- 如何取得知识库 ID；
- 冒烟运行、完整运行和恢复运行命令；
- 指标含义与限制；
- 主实验为何关闭 Web 搜索。

## 错误处理

- 单题或单模式失败不终止整个实验。
- 失败记录必须包含阶段、异常类型和可读错误信息。
- 数据集启动时执行 schema、ID 唯一性、文档名和题型校验；标注无效时应在产生模型费用前失败。
- 输出逐题写入并及时刷新，使进程中断后可以恢复。
- 汇总中单独列出运行失败和 Judge 失败。

## 测试

单元测试覆盖：

- 数据集 schema 和唯一 ID 校验；
- 文档命中、事实覆盖、引用有效性和拒答指标；
- 失败样本仍进入汇总分母；
- Judge 失败降级；
- JSONL/JSON/Markdown 结果落盘；
- `--resume` 跳过已成功组合，但允许重试失败组合。

冒烟测试使用 `--limit` 和单一模式验证真实执行路径与结果格式。完整实验使用当前已索引的 `RAG Evaluation` 知识库运行三种模式。

## 验收标准

- 评测集包含 18 题，覆盖四类题型，且每题都有人工参考答案和来源标注。
- 同一命令可对任意给定知识库 ID 运行三种模式。
- 主实验完全不依赖 Web 搜索。
- 中断后可恢复，不重复计算成功样本。
- 每次运行生成可审查的逐题和汇总产物。
- 测试通过，并完成一次真实全量实验。
- README 与 DEVELOPMENT 只展示本次可复现实验实际得到的数据和运行条件。
