# 平衡型 Auto RAG 路由设计

## 背景

2026-07-29 的固定语料评测显示：

- Standard 的平均延迟为 11.65 秒，但多文档答案正确性只有 0.150。
- Agentic 的多文档答案正确性达到 0.980，但平均延迟为 65.36 秒。
- Auto 的多文档答案正确性为 0.180，平均延迟为 48.01 秒，没有形成理想的质量与延迟折中。

逐题检查发现，Auto 将三道多文档综合题错误路由到 Standard，同时将部分单文档事实题路由到 Agentic。当前路由完全依赖一次 LLM 判断，既不稳定，也缺少可解释的兜底信号。

## 目标

- 明确的复杂问题稳定进入 Agentic。
- 明确的简单问题稳定进入 Standard。
- 模糊问题继续使用 LLM 判断。
- 降低 Auto 的 Agentic 检索预算，控制平均延迟。
- 让路由原因、判断来源和最终预算可观测、可回归。

## 非目标

- 不改变强制 `standard` 或强制 `agentic` 模式的行为与预算。
- 不修改最终答案生成的超时和重试策略。
- 不根据 HTTP、Cookie、Promise 等评测领域关键词硬编码路由。
- 不重新设计检索、重排或回答提示词。
- 不在本阶段启用 Web 搜索。

## Auto 路由架构

在现有 LLM 查询分析前增加确定性结构分析层。该层只分析问题形式和信息需求，返回：

- `force_agentic`：问题有明确复杂信号，直接进入 Agentic。
- `force_standard`：问题有明确简单信号，直接进入 Standard。
- `needs_llm`：规则无法可靠判断，调用现有 LLM 分析。

### 复杂信号

以下结构可触发 `force_agentic`：

- 明确比较或对照两个对象；
- 同时询问多个独立对象或多个问题；
- 要求综合不同主题、来源或规范；
- 要求先取得一个事实，再基于它推导另一结论；
- 要求解释多个阶段或多个机制之间的关系。

规则应使用通用句法和意图信号，例如比较词、并列问句、关系词和多跳表达。规则不得包含评测语料的领域实体名称。

### 简单信号

满足下列条件时可触发 `force_standard`：

- 单一对象的定义；
- 单一属性、用途或事实查询；
- 问题不包含比较、并列、多跳或跨来源信号；
- 不依赖对话上下文补全指代。

### LLM 判断

`needs_llm` 继续调用 `analyze_query_complexity`。LLM 负责处理含糊表达、上下文指代和规则无法覆盖的自然语言变体。

LLM 调用失败时：

- 已存在复杂信号但不足以强制路由的查询进入 Agentic；
- 其余查询进入 Standard；
- trace 记录完整降级原因。

## 路由结果模型

查询分析输出扩展为可解释结果，至少包含：

- `is_complex`；
- `sub_questions`；
- `route_source`：`rule`、`llm` 或 `fallback`；
- `route_reason`：命中的规则、LLM 决策或失败原因；
- `complexity_signals`：提取到的结构信号。

Auto 执行 trace 增加：

- `auto_route`；
- `route_source`；
- `route_reason`；
- `complexity_signals`；
- `auto_max_retrieval_rounds`；
- `auto_max_total_retrieval_calls`。

这些字段用于评测、Debug Panel 和生产日志，不改变 Standard/Agentic 的回答接口。

## 子问题拆分

复杂问题的有效拆分必须满足：

- 包含 2–3 个子问题；
- 每个子问题只有一个检索意图；
- 保留原问题中的关键限定词；
- 去除完全重复、规范化后重复及明显包含关系的子问题；
- 每个子问题都能独立用于一次知识库检索。

LLM 返回超过 3 个子问题时，保留覆盖原问题主要信息需求的前三个。过滤后少于两个子问题时，不降级到 Standard；使用原问题作为单个 Agentic 检索意图。

本阶段不再进行第二次 LLM 拆分修复，避免为了修复路由增加额外模型调用。

## Auto 成本控制

仅 Auto 路由到 Agentic 时使用更保守的预算：

- 每个子问题最多 2 轮检索；
- 整个请求最多 6 次检索；
- 上下文达到充分阈值时立即结束当前子问题；
- Web 搜索默认关闭。

强制 `agentic` 模式继续使用现有每子问题最多 3 轮、全局最多 8 次检索的预算。这样保留稳定的高质量消融基线，也让 Auto 可以优化质量与延迟折中。

为支持不同全局预算，`prepare_agentic_answer` 和状态初始化接受显式的
`max_total_retrieval_calls`，默认值保持 8，只有 Auto 传入 6。

## 数据流

1. Auto 收到问题和对话历史。
2. 确定性结构分析提取复杂度信号。
3. 规则返回 `force_standard`、`force_agentic` 或 `needs_llm`。
4. `needs_llm` 调用现有 LLM 查询分析并合并可观测字段。
5. Standard 路径执行一次检索。
6. Agentic 路径验证、规范化子问题，并应用 Auto 专用预算。
7. 统一回答模块生成一次最终答案。
8. trace 返回路由来源、原因、预算和检索执行数据。

## 错误处理

- 规则分析不得因无法识别句式而抛错；无法判断时返回 `needs_llm`。
- LLM 分析超时、空响应或非法 JSON 时进入确定性降级路径。
- 无效子问题不导致复杂查询降级到 Standard。
- Agentic 准备流程失败时继续沿用现有 Standard 安全降级，并保留 `fallback_from` 和错误原因。
- 路由失败、检索失败与最终生成失败保持不同 trace/错误阶段，便于后续可靠性治理。

## 测试

### 路由单元测试

覆盖：

- 比较问题；
- 多对象并列问题；
- 跨来源综合问题；
- 多跳推理问题；
- 单一事实问题；
- 定义问题；
- 含糊追问；
- LLM 分析失败；
- 对话历史中的指代。

测试断言最终路由、`route_source`、`route_reason` 和复杂度信号。

### 拆分单元测试

覆盖：

- 重复子问题；
- 空拆分；
- 超过三个子问题；
- 非字符串值；
- 只有一个有效子问题；
- 限定词保留；
- 无效拆分仍保持 Agentic 路径。

### 执行集成测试

验证：

- Auto 的规则 Standard 路径不调用分析 LLM；
- Auto 的规则 Agentic 路径使用 2/6 预算；
- 强制 Agentic 仍使用 3/8 预算；
- LLM 模糊路由沿用统一执行入口；
- trace 包含完整决策信息。

### 评测回归

仅重新运行 18 题的 Auto 模式，并与已记录的 Standard/Agentic 基线比较。评测保持：

- 同一知识库与固定语料；
- `top_k=5`；
- Web 搜索关闭；
- 相同确定性指标与 LLM Judge。

## 验收标准

- 五道多文档综合题全部进入 Agentic。
- 两道指南/规范对照题全部进入 Agentic。
- 八道单文档事实题至少六道进入 Standard。
- Auto 多文档答案正确性不低于 0.80。
- Auto 整体文档召回率高于 0.767。
- Auto 平均延迟不超过 45 秒，并低于纯 Agentic 的 65.36 秒。
- Auto 无答案正确率保持 1.000。
- 主评测中 Web 搜索使用次数为零。
- 现有测试及新增测试全部通过。

## 实验结果

确定性路由和强制拆分达到主要质量目标：

- 五道多文档题和两道指南/规范题全部进入 Agentic；
- 八道事实题中七道进入 Standard；
- 文档召回率 0.933；
- 多文档答案正确性 0.900；
- 整体答案正确性 0.856；
- 无答案正确率 1.000；
- Web 搜索使用次数为零。

2/6 预算的平均延迟为 55.28 秒，没有达到 45 秒目标。后续 2/4 消融实验
将平均延迟降到 43.43 秒，但多文档正确性同时降到 0.590。项目因此保留
2/6 预算，把减少 Agentic 内部串行 LLM 调用作为后续性能工作，而不再以
牺牲检索覆盖换取延迟。实现完成后后端测试总数为 109。
